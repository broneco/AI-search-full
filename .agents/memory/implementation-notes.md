Read docs/releases/v0.1.6.md for shipped behavior and migration boundaries. Runtime private APP_VERSION may still override the new source version during a later deployment.

- Latest connectivity priority (2026-10-21): avoid assuming a new VM is necessary. Evaluate userspace OpenVPN-to-proxy in a bounded non-root Docker spike, then ACA sidecar only if proven. See handoff variant D. go-openvpn rejects supplied comp-lzo; Tuna/tunpipe are patched community candidates, not verified deployment dependencies. - JHU connectivity/KV plan (2026-10-21) is in .agents/inbox/2026-10-21-jhu-connectivity-keyvault-handoff.md; no connector implemented yet. Existing prod secrets are already SDK-resolved from KV under backend Secrets User. Local/test intentionally bypass KV, so future JHU-only opt-in must preserve loopback DB isolation. API Basic credentials differ from VPN credentials. External Client.ovpn has CA/user-password auth, no private key; reconnect/MFA/simultaneous sessions need proof. Current ACA has platform network, so private gateway requires new VNet environment; HTTPS application gateway can work with existing public egress. Do not assume a privileged TUN sidecar or import .ovpn into Azure S2S. New VM identity is not ACA identity and needs separately authorized admin RBAC. Never copy local known default JWT to KV, rotate deployed signing/legacy keys, delete DPAPI rollback snapshots or commit VPN/auth files as part of secret cleanup.

- ADR-0037: output budget UI lives in ModelManagementPanel → App configuration. model_runtime_settings uses exact tenant hash/model ID, max_output_tokens nullable override, independent revision/author/time. NULL reset retains revision (no ABA). model_catalog(runtime_settings=False) exposes the immutable base for editing/bounds; default catalog applies validated runtime copies. New chat/summary/classification providers and DB-backed implicit tagger/CLI see overrides, in-flight provider snapshot unchanged. Local pinned context reserves 1024 input + 256 overhead; legacy no-context local can only lower its configured cap. Increase output reduces input budget; never truncate/reembed/change digest. Azure max_completion_tokens and Ollama options.num_predict (including legacy) enforce min(internal cap, profile cap). Optional missing SQL table preserves defaults; writes require migration, other permission errors fail closed. Shared metadata_rows helper powers descriptions/limits with separate error prefixes and tables. Local startup creates table, cloud excludes it and uses migrate_model_limits.py + handoff.

- ADR-0036: admin ResultsComparison uses two ordinary /api/chat calls with separate thread IDs and per-turn model/index/filter snapshots. One shared input, no index fan-out, auto-retry or fallback. Both variants touching JHU (LLM or query embedding) run A → B because inference and embeddings share the same semaphore; admin index metadata exposes embedding_location, unknown older metadata schedules conservatively. Logout aborts queued work and clears citations. ModelManagementPanel merges configured models, publication, ACL and descriptions; discovery stays read-only in a native modal. model_descriptions stores editable CS/EN separately from immutable registry/vector identities, exact tenant hash + model ID, CAS revision/author/time. Local startup creates it; cloud excludes it and uses migrate_model_metadata.py + handoff. Public authorized /models includes descriptions/purposes/operational limits. Prompt task PUT changes only summary_custom_prompt or analysis_rules using existing config managers; no category/ACL migration or automatic reindex. Unsaved language/prompt/model-management drafts survive tab changes.

- ADR-0035: runtime local profiles/publication live in SQL tenant_model_registry, layered over file catalogs. Registry reads preserve old installs when the table is absent, but registration requires migration and other SQL errors fail explicitly. Startup only creates it locally; Azure has migrate_model_registry.py + handoff. Metadata-only discovery never approves; registration rechecks model/digest/kind/dimensions/context and user group, pins an immutable snapshot and does no inference. Existing local chat IDs retain public visibility when first pinned; changed digest gets another ID. Embedding IDs include recipe fingerprint; do not key only on model name/digest or silently overwrite an approved transform. Nomic reuses its existing profile and MXBAI has its own versioned query prefix. Both consoles select exactly one prepared UUID. Ordinary users require publication plus group policy; /available excludes hidden models before coverage and exposes no corpus counts. Backfill, role revocation, ACL and ingestion-default rules remain unchanged.

Keep the shared catalog/index hooks in page scope and panels mounted while hidden so tab switches do not reset in-flight work or draft access rules. Prompt loads once per backend/tenant/auth identity, preserves per-language drafts across tab switches, and saves only explicitly. Chat/document operations show selections and link back; one UUID per query/default ingestion semantics remain unchanged. This is layout-only and does not add model downloads or approval registry behavior.

Chat's optional search_index_id is Management-only and pins known profile/complete coverage/one VectorSearchPlan table before query embedding and thread writes. Missing/foreign/incomplete/unknown-profile selections fail without fallback. UI labels and saved generation retain actual index/model. New upload may make inactive experiments incomplete; re-prepare them. - Discovery remains metadata-only and Management/tenant-scoped: app/providers/model_discovery.py, GET /api/models/discovery, admin ModelDiscoveryPanel. Explicit registration/publication is implemented separately by ADR-0035, and both consoles have one-index UUID selection. Never infer approval from a scan, fan out or change ingestion from a query. Live metadata admitted 13 chat/2 embedding models and excluded 2 rerankers; only a small Llama/MXBAI RAG path was generated live, not all 13 models. - Local embedding implementation: docs/development/local-embeddings.md and ADR-0032. embedding_config is a whole-file tenant catalog separate from LLM model_config. Preserve original Azure profile identity; JHU Nomic uses digest + prefixes + dimensions + L2 identity. Active index chooses query and ingest provider; no same-dimension substitute. Explicit backfill retains chunk IDs/legacy vectors; new ingest updates the active space, so other indexes may need backfill before rollback. Same JHU credentials/VPN guard and process slot as inference, no truncation/retries/fallback. Never auto-update a mutable model digest or auto-activate an experiment. Native Azure networking/storage/performance acceptance remains separate from local SQL/JHU proof.

Model-selection design/checklist is in docs/architecture/model-catalog-roadmap.md, local instructions in docs/development/model-selection.md. Profile identity is separate from embedding space and credentials. Model access is SQL data, not mutable container files. Null/all and []/deny semantics, tenant scope, CAS revision and fresh group checks must be preserved. JHU inference uses Basic POST /api/generate and no provider fallback; embedding uses its own /api/embed contract. The ignored .env.jhu-model must never enter source exports or logs. Windows OpenVPN was verified locally; Azure connectivity is unproven. Summary failures in production must propagate before replacing records/embedding text, never persist preview placeholders.

- Source release / JHU source handoff / Azure deployment are separate operations. Before future JHU work read .agents/workflows/jhu-publication.md. Versioned root export_jhu.py and prepare_jhu_publication.py replace ignored prototype operators; they read committed Git snapshots and use current-state templates. Export provenance is an internal sidecar, never customer history. Sync defaults to plan and validates origin/main/clean tree/expected HEAD/paths before Apply; it never commits, pushes or touches cloud resources.

- Tenant data identity is exact and case-sensitive where supported. Configuration directory aliases are centralized in app/core/tenant_identity.py; aliasing never grants access or changes persisted IDs.
- Search prefilters are shared across vector and keyword branches. Eligibility includes server-derived tenant/groups, both ACL levels, metadata and freshness before top K. Hydration/context/history recheck access and revisions.
- Embedding profiles identify the space, not the endpoint. Same dimensions do not imply compatibility. Text changes invalidate all profile embeddings; chunk deletion cascades. Native exact and optional DiskANN use the same catalog/profile/revision checks.
- Default mode is exact. ANN requires a real enabled cosine v3+ index; index creation does not activate it. Timeouts do not launch another scan. JHU metadata-filter ANN performance remains unresolved.
- Main ingestion generates replacement embeddings before deleting old records, then writes document/chunks/ACL/profile vectors transactionally. force_reindex bypasses the unchanged-file shortcut for explicit refresh.
- Administrative refresh captures exact tenant scope. Input validation and classification precede replacements; only initial, unchanged stale IDs can be pruned after all files succeed, using conditional deletes. Failed runs can retain successful replacements but do not prune the rest. Newly uploaded rows are not stale candidates.
- Fast reindex requires the exact stored source under data/. A missing source preserves existing chunks and reports failure; a same-basename file elsewhere is never substituted.
- Use full_refresh_ingest.py without --apply for a source/target plan. Cloud apply requires expected host/database/tenant. The CLI cannot silently change the configured database/model tenant. No automatic bulk clear or root data fallback.
- ask.py is an HTTP client: prompted email/password or AI_SEARCH_TOKEN, same server authentication/ACL as the UI. No direct FastAPI handler calls or local DB initialization.
- Backend and frontend deployment scripts are separate existing-resource plan/apply tools. Frontend requires confirmed subscription/directory, checks native exit codes, never creates SWA and never echoes the deployment token.
- Canonical Python dependencies and package discovery are in pyproject.toml; requirements.txt installs .[dev]. Public tenants/fixtures are sibling namespace resources in the wheel; private env files are explicitly excluded. Repository and installed paths retain the same relative resource layout.
- Azure SDK configuration loads at process import. local/test skips Key Vault; cloud supports runtime secrets/managed identity. Passwords use Argon2id; explicit legacy password key is separate from signing. Current tokens are custom signed bearer tokens despite historical JWT variable names.
- Tests globally replace the SQL engine/session before importing routes; native/local SQL tests are opt-in and separate from unit evidence. Real-env structural checks inspect configured tenant files only and require no fixed count of ten; synthetic fixtures cover the one-tenant case on clean clones.
- Windows PowerShell 5.1 treats native stderr warnings as error records; helper functions must judge native commands by exit code. Keep SQL NOCOUNT/timeouts scoped on every success/error/cancellation path.
- Azure VECTOR JSON parameters need NVARCHAR(MAX); vector-index DDL needs its own AUTOCOMMIT connection, not a user transaction. Preserve correlated ACL EXISTS/type bindings when compiling textual ANN batches.
- Native keyword uses bounded Unicode CONTAINSTABLE terms and deferred legacy embedding hydration. Local SQL 2022 reference uses JSON cosine/LIKE and does not prove native Azure fulltext/ANN performance.
- Python reference version is 3.12. Next.js dependency versions are pinned by package locks. Current frontend builds are static exports.
