# Current Project State

This is the standalone JHU AI Search repository, source version @@VERSION@@. It starts with a single snapshot commit; no original development Git history or operational diary is imported. Future updates are normal reviewed commits in this repository. Do not merge/mirror unrelated history or force-push.

Only tenants/jhu is bundled, including search/classification configuration and the JHU frontend theme/logo. Local identity is jhu; cloud corpus identity is ju-prod. Configuration aliases never change database/token/ACL identities. Private env, documents, dependencies and caches are excluded.

Current design: FastAPI, synchronous SQLAlchemy, two Next.js static frontends, Azure SQL native exact + fulltext and optional DiskANN v3+, Azure OpenAI factories, Blob Storage and optional Key Vault. Tokens are custom signed bearer tokens and passwords Argon2id. Local SQL 2022 uses the JSON/LIKE reference.

Management can edit maximum output tokens or restore the default in the model overview. SQL model_runtime_settings is exact-tenant scoped with independent revision/null reset, separate from immutable JSON/registry snapshots. New chat/summary/classification operations use the effective limit; local context bounds reserve input and no text is truncated. Both adapters cap internal generation requests too. Local startup creates the table; Azure requires separate guarded migrate_model_limits.py. See docs/development/admin-comparison.md.

Admin **Porovnání výsledků** sends one question to two independent standard chat threads, each with one model/index and separate filters/history/errors. Both variants using JHU inference/embedding run A → B for the shared slot; other pairs may run concurrently. **Modely a vyhledávání** contains searchable model pickers, unified configured-model/publication/group table and editable CS/EN descriptions. API discovery opens in a modal and never auto-approves models. Descriptions use exact-tenant SQL `model_descriptions` with CAS revision, separate from immutable model/embedding identity; cloud needs guarded `migrate_model_metadata.py`, never startup DDL. The last section edits RAG, summary and classification instructions; document prompt writes patch only their existing config fields. See docs/development/admin-comparison.md. No AI automatic router or multi-index retrieval is implemented.

Run and record unit, package and frontend verification for every prepared snapshot. These checks are not a cloud deployment or performance acceptance.

Known deferred work: experimental PostgreSQL retrieval, OCR, main-pipeline section_title persistence, Blob/local configuration unification, automated model comparison. Default search remains exact; do not activate ANN or change capacity without target evidence and authorization.

Read README.md, docs/architecture/search.md, docs/deployment.md and docs/updates.md. Preserve tenant secrets, user data, accounts and Docker volumes. Cloud changes require explicit scope and guarded target checks; publishing source alone does not authorize them.

Local-model registry and user-app index exposure are implemented. See docs/development/local-model-registry.md. Management explicitly adds compatible discovered LLM/embedding profiles, optionally publishes them with revisioned checkboxes, then prepares embedding indexes locally. Users see only published/group-authorized complete indexes and choose one UUID; no fan-out/fallback or ingestion activation. Existing Qwen and Nomic identities are preserved; changed digest or embedding preprocessing gets a new profile. Next verify Czech relevance on the same PDFs/questions across selected small LLMs and Azure/Nomic/MXBAI; cloud rollout and ANN performance remain separate.

Model selection is implemented through model_config.json, bound Azure/JHU providers and current server-group authorization. Both consoles select the chat model; the admin console also selects independent summary/classification models and edits model access. Read docs/development/model-selection.md and docs/architecture/model-catalog-roadmap.md. Public profiles do not prove deployed availability; verify networking, deployment existence and model_access_policies migration before cloud rollout. Never copy private model env into source or images.

JHU Nomic embedding support is implemented separately from LLM selection; read docs/development/local-embeddings.md. Runtime selects the provider from the active index; explicit backfill creates another space without duplicating chunks. Azure remains the default until guarded activation. Cloud networking, native acceptance and Czech relevance remain separate acceptance steps.

Management admin UI prepares/resumes local embedding indexes. Both consoles select one index UUID per question without activating it for ingestion. Complete coverage/profile/tenant checks precede query embedding; user publication/group rules are enforced server-side and never grant document access. No fallback/fan-out. Per-answer/history provenance retains the actual embedding/index. Cloud index writes remain separate guarded operator work.

Admin **Modely a vyhledávání** replaces the old prompt tab and contains model selection for answers/documents, embedding preparation/selection, discovery, access rules and prompt editing. Chat and document tabs show current choices with links back. Keep shared hooks and hidden management panels mounted across tab switches, preserving selections and drafts. API discovery only loads metadata; it does not download or approve models.
