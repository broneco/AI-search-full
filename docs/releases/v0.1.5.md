# v0.1.5 — bezpečná údržba, cleanup a reprodukovatelné předání JHU

Vydání zdrojů: **2026-10-16**, větev `microsoft-sql`. Verze backendu, obou frontendů, lock souborů a UI je sjednocená na v0.1.5. Toto vydání publikuje změny do hlavního GitHub repozitáře; neprovádí Azure release ani automatickou aktualizaci Forgejo.

## Opravy

- Fast reindex zpracovává pouze přesný tenant. Chybějící zdroj nezamění za stejnojmenný soubor jinde; zachová původní chunky a ohlásí chybu.
- Full refresh sdílí API/CLI službu, validuje zdroje a nepředmazává korpus. Embeddingy vzniknou před náhradou dokumentu; stale cleanup proběhne až po úplném úspěchu. Nové uploady a souběžně změněné stale řádky jsou chráněné. Vztahy se přesměrují na nová UUID uvnitř tenantu. Pozdější chyba může ponechat hotové individuální náhrady, nikoli promazat zbytek.
- Detekce vztahů neposílá modelu názvy cizích dokumentů a odmítá nepovolené target UUID.
- `ask.py` používá autentizované HTTP API včetně serverových ACL místo přímého volání handleru.
- Frontend deployment má read-only plán, potvrzený existující cíl a správné chybové exit kódy. Nevytváří SWA a nehádá backend URL.
- Sdílený alias ju → jhu sjednocuje env/JSON načítání bez změny přesné identity ju-prod.
- Python wheel obsahuje všechny backendové subpackages a veřejné JSON/PDF resources, bez privátních env. Závislosti jsou kanonicky v pyproject.toml; requirements instaluje .[dev].
- Testy nepotřebují deset privátních env ani všechny skutečné klienty. Jeden vyplněný tenant stačí; fallback/prompt izolaci ověřují syntetické fixtures.

## Cleanup a návody

README odpovídá dev.ps1, VS Code tasks a samostatným release skriptům. Changelog je pod docs/, PostgreSQL Compose je označený jako legacy, nepoužité scratch/recovery soubory, generované metadata/ARM a neplatné frontend workflow jsou odstraněné. Používané CLI, zdroje, vlastní data, env, volume a privátní rollback podklady jsou zachované.

Agentový kontrakt a krátká paměť popisují skutečné Azure SQL/provider/auth chování; starší poznámky jsou v hlavním repozitáři archivované.

## Předání JHU

Nové `export_jhu.py` a `prepare_jhu_publication.py` vytvářejí reprodukovatelný JHU-only snapshot z commitnutého refu a bezpečný plán/apply do nezávislého checkoutu. Nástroje necommitují, nepushují ani nenasazují Azure. Templates a [podrobný AI workflow](../../.agents/workflows/jhu-publication.md) jsou verzované a nevyžadují původní .local operátory.

JHU repo nadále začíná vlastním úvodním snapshotem; žádný původní Git graf, interní changelog, archiv paměti nebo provozní deník se nepředává. Každá další publikace je vlastní navazující souhrnný commit. Samotný v0.1.5 GitHub release tento cíl nemění.

## Ověření a hranice

Výsledky finálních kontrol jsou v changelogu a aktuální projektové paměti. Export/sync testy používají skutečné dočasné Git repozitáře bez sítě. Package test sestaví wheel a importuje jej mimo checkout. Frontendy se ověřují samostatným produkčním buildem.

- Kompletní izolovaná sada včetně wheelu: **280 passed / 84 expected skips**.
- V sadě je **18** export/sync regresí včetně ochrany Windows variant `.GIT`/`.ENV`.
- Produkční build uživatelské aplikace i administrace: **passed**.
- Docker Engine a localhost SQL nebyly 2026-10-16 dostupné. Opt-in SQL pokus skončil na connection setup; nová databázová/cloudová akceptace není deklarovaná.

Výchozí a dosud přijatý JHU search režim zůstává exact; ANN aktivace a reprezentativní p95 brány nejsou součástí releasu. PostgreSQL retrieval, OCR, hlavní section_title persistence, sjednocení Blob/lokální konfigurace a lokální modelové adaptéry zůstávají odložené. Privátní env může přepsat APP_VERSION; skutečnou runtime verzi prověř až při samostatně schváleném Azure releasu.
