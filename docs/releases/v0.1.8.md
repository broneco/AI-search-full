# v0.1.8 — stabilizace JHU a zachování dat

Vydání zdrojů 30. 10. 2026 pro hlavní GitHub a samostatný JHU Forgejo snapshot. Samotná publikace zdrojů nemění běžící Azure aplikaci, její konfiguraci, indexy ani kapacity.

## Co se změnilo

- Prompty, chunkování/vyhledávání a nastavení shrnutí/klasifikace v cloudu používají přesně tenantovanou SQL tabulku `tenant_settings`. Výchozí JSON se použije jen při chybějícím řádku. První převod vyžaduje zachycení současných hodnot a guarded insert-only migraci; běžný restart nic nepřepisuje.
- JHU cloud používá samostatný userspace VPN sidecar s Managed Identity a Key Vault bootstrapem. Lokální managed režim zůstává samostatný. Release automaticky nemigruje SQL, nestahuje modely ani neaktivuje indexy.
- Přehled dokumentů používá dávková ACL-scoped čtení; blokující SQL běží mimo hlavní async smyčku. Exact retrieval používá ověřený SQL join plán. Oprávnění, embeddingové profily a pořadí výsledků zůstávají zachovány.
- Obě konzole zvládají gateway chyby a opakované načtení katalogů, chrání novou relaci před starou 401 a vysvětlují neaktivní odeslání. Explicitně zvolený model/index se tiše nenahrazuje. Správní obnova JHU připojení funguje i v sidecar režimu.
- `verify_deployment.py` vytváří read-only checkpointy a striktně porovnává SQL, všechny indexy, konfigurace a volitelně skutečné Blob bytes přes výměnu image. Obsah ani credentials do otisků neukládá.
- Forgejo dostává úplnou veřejnou dokumentaci: README, architekturu, provozní návody, release/deployment reporty a podrobná vysvětlení testů. Vynechávají se ADR soubory, privátní env/data/cache a archiv interní agentní paměti. Runtime a branding zůstávají pouze JHU; historie obou Gitů jsou oddělené.

## Doložený provoz a hranice

[Skutečný test nové image](../deployments/2026-10-30-preservation-test.md) zachoval shodné otisky 4 účtů, 45 konverzací, 72 zpráv, 431 dokumentů, 9 372 chunků, ACL, nastavení a obou kompletních vektorových indexů. Shodovalo se také všech 431 původních Blob souborů. Je to důkaz konkrétního nasazení; nenahrazuje zálohy, restore drill ani validaci budoucích migrací.

[Stabilizace](../deployments/2026-10-30-cloud-stabilization.md) měřila přehled dokumentů přibližně 22 s → 0,281 s a indexů 14 s → 0,172 s. Latence generace závisí na provideru a modelu. SQL bylo na výslovný souhlas dočasně změněno S0/10 DTU → S2/50 DTU; tato zdrojová publikace kapacitu dále nemění.

Relevance zůstává otevřená: explicitní test R_583 s Azure indexem citaci našel, stejný test s Nomic indexem ji nevrátil. Nový index tedy není automaticky kvalitnější. Poslední ověření zachování dat neobsahovalo nové GUI/password-login ověření, protože nástroj pro prohlížeč nebyl dostupný; autentizované API, existující historie, PDF a oprávnění prošly. Celková produkční akceptace ani ANN benchmark nejsou uzavřené.

## Ověření zdrojového vydání

Úplný hlavní běh s lokální SQL a skutečným wheelem dokončil 720 testů úspěšně a 23 očekávaně přeskočil; jediná chyba byla pevně zadaný počet kapitol v novém dokumentačním testu. Po opravě na porovnání celého runbooku prošel finální publikační modul 20/20.

Čistý JHU balíček bez privátních env: **542 passed / 139 expected skips**, včetně skutečného wheelu. Testovací baseline pro syntetické tenanty je samostatná a nemění runtime konfiguraci. Oba produkční frontend buildy a TypeScript prošly v hlavním stromu (Turbopack) i v JHU balíčku (Webpack se sdílenými uzamčenými závislostmi). Frontendové regrese odolnosti 8/8; kontrola 13 známých privátních hodnot bez shody, syntaxe, verze, navigace a odkazy prošly.

Živé modely, Azure nasazení ani nový výkonový benchmark se při této zdrojové publikaci nespouštěly. Dřívější skutečné cloudové výsledky a otevřené otázky jsou odděleně uvedené v provozních reportech výše.
