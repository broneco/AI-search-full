# v0.1.4 — Azure SQL vyhledávání a lokální vývoj

Vydání: **2026-10-15**. Zahrnuje změny od v0.1.3 ve větvi `microsoft-sql`; verze backendu, obou frontendů, jejich package locků a UI je sjednocená na v0.1.4.

Hlavní změnou je vyhledávání nad profilovými vektory v Azure SQL se společnými filtry a oprávněními, doplněné o nativní fulltext. Součástí je trvalé lokální prostředí z VS Code, testovací dokumenty, bezpečnější autentizace, migrační nástroje a reprodukovatelná evaluace.

**JHU používá nativní přesné hledání (`exact`). DiskANN je volitelné rozšíření, ve výchozím stavu vypnuté.** Fyzický index v3 existuje, ale jeho vytvoření samo ANN nezapíná. U některých filtrovaných dotazů bylo ANN pomalejší a timeoutovalo, proto se neaktivovalo. Release neobsahuje automatické přepínání režimů ani náhradní scan po timeoutu.

## Vyhledávání a embeddingové modely

- Neměnný `EmbeddingProfile` identifikuje model, revizi, rozměry, normalizaci a zpracování vstupu včetně odlišných prefixů pro dotazy a dokumenty. Dva modely se stejným rozměrem se nepovažují za kompatibilní; nesoulad se odmítá před hledáním.
- Výběr embeddingového i odpovědního provideru sjednocuje factory zapojená do chatu, ingestace, taggeru a náhledu. Dokumenty používají `embed_documents`; výsledky dávek se kontrolují včetně pořadí, rozměrů a konečnosti hodnot. Implementovaný provider zůstává Azure; lokální modelový adaptér zatím není součástí vydání.
- Katalog odděluje embeddingový profil a logický index. Každý profilový index má vlastní vektorovou tabulku; texty ani ACL se mezi indexy neduplikují. Běžný dotaz používá jeden aktivní index tenantu; další indexy se připravují explicitně pro experimenty.
- Azure přesná cesta používá nativní `VECTOR` a `VECTOR_DISTANCE` nad všemi způsobilými chunky před finálním top K. Odstraňuje dřívější arbitrární limit 600 kandidátů. Lokální SQL Server 2022 poskytuje úplnou přesnou JSON referenci s průběžným výběrem top K.
- Transakční repository synchronizuje chunky, vektory, profil, revizi vstupu a ACL. Změna textu zneplatní embeddingy ve všech indexech, smazání chunku je kaskádově odstraní. Chyba ingestace nebo reindexace vrací původní databázový stav.
- Backfill vytváří nové embeddingy existujících chunků bez nové extrakce či chunkování, kontroluje současnou revizi a omezuje zbytečné načítání starých JSON vektorů. Historické JSON embeddingy se zachovávají a nepřebírají se bez prokazatelného profilu.

## Filtry, oprávnění a keyword větev

- Vektorová i keyword větev používají společné parametrizované tenant, dokumentové ACL, chunkové ACL, metadata a freshness filtry **před top K**. Relační ACL projekce mají indexy a synchronizují se se zápisy.
- Identitu tenantu a skupiny určují ověřený token a aktuální databázový účet. Hlavičky `X-User-*`, automatický výběr uživatele a fallback mezi tenanty již neurčují oprávnění.
- Rozšíření kontextu, historie konverzace a PDF náhled znovu ověřují přístup. Staré odpovědi bez ověřitelné evidence se redigují; oba frontendy načítají PDF autentizovaně.
- Azure keyword větev používá `CONTAINSTABLE` místo nákladného `LIKE` scanu. Dotaz je omezený Unicode parametr tvořený citovanými slovy; uživatelská fulltext syntaxe se nepřebírá. Globální fulltext cap nesmí předcházet filtrům. Hydratace textu nečte staré JSON embeddingy.
- JHU fulltext byl ověřen s českým jazykem 1029. Lexikální vyhledávání nyní pracuje se slovy podle fulltext pravidel, což se liší od původního hledání podřetězců. Při chybě či timeoutu se nespouští další nákladný scan; lokální reference zůstává oddělená.
- Opraven chat HTTP 500 způsobený násobením `float` a SQL `Decimal` v hybridním skóre. SQL Server ukládá názvy dokumentů/konverzací a texty chunků/zpráv jako Unicode.

## Volitelný DiskANN a diagnostika

- Režim `exact` je výchozí i při chybějícím nastavení. Explicitní `ann` vyžaduje kompatibilní povolený cosine index verze alespoň 3 a správný profil. Chybějící index se neskrývá přechodem na jiný model.
- `VECTOR_SEARCH` používá stejné prefiltry, úplnou SQL materializaci způsobilých ID/revizí bez kandidátního capu a kontrolu revize při hydrataci. Vynucené ANN umožňuje rozlišit skutečný přibližný plán od přesné reference.
- Opraveny skutečné Azure/ODBC rozdíly: dlouhé JSON parametry pro `VECTOR`, SQL typy a korelace ACL, fulltext parametr a vytvoření vektorového indexu mimo uživatelskou transakci.
- Scope SQL timeoutu a `NOCOUNT` se obnovuje i po chybě. Diagnostika rozlišuje skutečný režim, profil/index a časy vector, keyword, fusion a expansion; chyby vracejí řízené 503/504.

## Lokální vývoj a testovací data

- `dev.ps1`, `docker-compose.local.yml` a sdílené VS Code tasks spouštějí SQL Server Developer, backend, frontend a izolované testy. Databázová data zůstávají v Docker volume i po restartu počítače; náhodné lokální heslo je v ignorovaném `.env.local`.
- Profily local/test oddělují databázi od cloudového prostředí, nenačítají tenantí cloud secrets ani Key Vault a ukládají runtime konfiguraci do ignorovaných overlay složek. SQLite unit testy, skutečné lokální SQL testy a opt-in Azure native testy mají oddělené role a ochrany cíle.
- Dva krátké české PDF dokumenty o fiktivní vysoké škole Aurora se lokálně automaticky a opakovatelně indexují; platné embeddingy ani vlastní dokumenty se při dalším startu nepřepisují. Přidáno osm českých smoke otázek.
- Opravena diagnostika Dockeru pro Windows PowerShell 5.1 i 7: varování na stderr již nezpůsobí falešné selhání při úspěšném návratovém kódu. Do Gitu se nezahrnují testovací cache, databáze, env ani provozní artefakty.

## Autentizace, secrets a nasazení

- Nová hesla používají Argon2id nezávislý na JWT klíči. Úspěšný legacy login může po ověření bezpečně převést starý hash pomocí tenant-scoped compare-and-set; chyba transakce nevydá token ani nepřepíše účet. Nejde o reset uživatelských hesel.
- JWT lze načíst z Key Vaultu s volitelným připnutím verze; legacy heslový klíč je oddělený. Doplněny potřebné identity/Key Vault a Argon2 závislosti. Cloud odmítá známý veřejný výchozí JWT klíč a nevytváří demo účty; registraci spravuje Management.
- Docker image má explicitní runtime obsah a základ Python 3.12 / Debian Bookworm. Env soubory, soukromé klíče, korpus, frontendy, testy, scratch a provozní zálohy se nebalí.
- `deploy_backend.ps1` má výchozí čtecí plán a potvrzení cíle; aktualizuje image existující app odděleně od migrací, ingestace a secrets. Starý kombinovaný `deploy_all.ps1` je blokovaný.
- Přidány auditní/migrační CLI pro schéma, ACL a vektorové indexy, návody, handoffy, ADR-0019 až ADR-0028, vysvětlení testů a paměť projektu. Privátní operátorské checkpointy a zálohy zůstávají mimo Git.
- Před publikováním odstraněno doslovné SQL heslo ze starších handoffů a infrastrukturních souborů. CLI provisioning vyžaduje bezpečně dodaný `AZURE_SQL_PASSWORD` nebo parametr; Bicep parametry čtou `POSTGRES_ADMIN_PASSWORD` z prostředí. Existující cloudové heslo se tím nemění. **Starší Git historie může obsahovat původní hodnotu; je potřeba její následná rotace.** Historie se tímto vydáním nepřepisuje.

## Evaluace a ověřené výsledky

Benchmark odděluje přípravu cache embeddingů od měření bez modelových volání. Porovnává ANN s přesnou referencí, kontroluje profil, korpus, aktuální oprávnění a pokrytí, rozlišuje selektivitu filtrů a zahrnuje celý retrieval. Reporty obsahují fingerprinty a agregované výsledky. Brány požadují průměrný recall@30 alespoň 95 % na nejméně 100 dotazech a p95 celého retrievalu do 1 s při souběhu 1 i 3 s nejméně 200 požadavky pro každý souběh; studený start se vykazuje zvlášť.

## Nasazení a další práce

Push této verze na GitHub neprovádí databázovou migraci ani aktivaci ANN. Pro ostatní prostředí je nutné samostatně ověřit tenant/schema, Unicode, relační ACL, profil a pokrytí vektorů, fulltext a konfiguraci secrets podle příslušných handoffů; nelze pouze přepnout legacy JSON na neprokázaný profil. Pro JHU se již dokončené migrace znovu nespouštějí. Návrat z budoucího ANN vede explicitním nastavením `exact` nad stejným profilem a nativní tabulkou.

Starý `infra/main.bicepparam` má již z předchozí verze PostgreSQL parametry, které současný `main.bicep` nedeklaruje; jeho kompletní kompilace proto selhává. Toto vydání v něm pouze odstranilo heslo a ověřilo nové načtení z prostředí izolovaně. Soubor není ověřeným postupem pro nové infrastrukturní nasazení; aktuální JHU image rollout ho nepoužívá.

Nejbližší navazující slice: reprezentativní JHU runtime benchmark podle selektivity filtrů a optimalizace změřeného zbývajícího nákladu, včetně rozšíření kontextu, před rozhodnutím o aktivaci ANN. Nadále jsou odložené opravy PostgreSQL operátorů, ukládání `section_title`, sjednocení Blob/lokální konfigurace, OCR, lokální modelové adaptéry a automatické porovnávání embeddingových modelů.
