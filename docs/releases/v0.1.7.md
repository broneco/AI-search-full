# v0.1.7 — automatické lokální JHU připojení a provozní odolnost

Vydání zdrojů: **2026-10-26**, hlavní GitHub repozitář, větev `microsoft-sql`. Backend, oba frontendové balíčky/lock soubory a UI používají v0.1.7. [Changelog](../CHANGELOG.md) obsahuje podrobnosti.

## Automatické připojení z notebooku

- VS Code úloha **AI Search: start JHU local app** a `dev.ps1 -Action backend -Tenant jhu -JhuManaged` zajistí vlastní lokální VPN helper; systémovou OpenVPN není potřeba ručně zapínat.
- Jeden společný transport pokrývá chat, shrnutí, klasifikaci, embeddingy, discovery a backfill. Výchozí direct režim a ostatní tenanty zůstávají dostupné.
- Non-root helper používá připnutý oficiální OpenVPN 2.7.8 a userspace forwarder bez host TUN, privilegovaných capabilities nebo změny hostitelských rout. Úzká loopback gateway povoluje pouze tags/show/generate/embed, ověřuje capability a nepovoluje libovolný proxy cíl nebo redirect.

## Secrets a životní cyklus

- Scoped Key Vault resolver odděluje VPN credentials helperu od API credentials backendu. Secrets ani soukromý VPN profil se nezapisují do image, argumentů příkazů, Docker env nebo zdrojového vydání.
- Backend ověřuje vlastnictví/protokol/cíl/mapování helperu a drží jeden API snapshot; Docker ani Key Vault se nevolají pro každou otázku. Chyba nevyvolá skrytý návrat ke starým env credentials.
- `jhu_connection.py` poskytuje idempotentní start/status/stop, explicitní reconnect/restart a omezený rozpočet obnovy. Terminální autentizační a certifikační chyby se neopakují v nekonečné smyčce.

## Výpadky a latence

- Ztráta připravenosti ukončí aktivní upstream sockety; gateway má celkový watchdog a neotevírá zrušený požadavek znovu. Odeslaná generace ani embedding se automaticky neopakují a nedochází ke změně modelu/indexu.
- `GET /api/models/connection` odděluje stav JHU od zdraví backendu. Management může přes `POST /api/models/connection/refresh` explicitně a atomicky načíst nové připojení/API snapshot bez restartu backendu; selhání zachová předchozí snapshot.
- Společný JHU slot se zabírá před externím lookupem; vytížená služba vrací řízenou chybu bez další fronty. Refresh drží slot do konce omezeného workeru i po odpojení volajícího.
- HTTP klienti sdílejí pouze ověřený SSLContext, aby opakovaně nenačítali certifikáty; klienti, cookies a event loopy se nesdílejí. Neúspěšné health kontroly odvolají ready okamžitě, VPN restartuje až třetí souvislá chyba.

## Vývoj a balení

- Backendový autoreload sleduje pouze `app/`; kopie Python souborů v testovacích adresářích nezpůsobují restartovací smyčku a opakované načítání Key Vaultu.
- Standardní pytest používá číslované, zamčené adresáře pod `.local/tmp/pytest/`, retenci tří posledních relací a `.local/pytest-cache/`. Smazáno 53 ověřených starých kořenových temp složek; soukromé env, korpus a Docker volumes zachované.
- Nestabilní benchmarková regrese s 1ms timerem používá řízené hodiny a ověřuje přesné latence dávek i souběh; produkční benchmark se nezměnil.
- Wheel i čistá JHU projekce zahrnují aktuální veřejné moduly/návody. Git, image, wheel a export vylučují soukromé `.ovpn`/`.auth`, credentials, cache a provozní artefakty.

## Ověření a hranice

Lokální skutečný RAG test prošel bez systémové VPN: discovery 17 modelů, Nomic dokumentové/query embeddingy, právě jeden vybraný druhý index, Llama odpověď s citací a uloženou provenance. Test používal dočasnou SQL databázi a zachoval původní chunky i aktivní referenční index.

Aktuální helper prošel fault/refresh/rekey testem: přerušení generace 281 ms, obnova pro nový dotaz 4 047 ms, soak 302 s ve stejné generation, 10 TLS kanálů a žádný replay. Health medián 16 ms; helper peak 37,6 MiB a průměr 0,0027 CPU jádra. Samostatný schválený restart Rancheru obnovil prostředí za 92,2 s dříve v témže slicu. Tyto výsledky nejsou benchmark celého RAG ani záruka dnů provozu. Dřívější jednotlivé modelové chyby a nečekané reconnecty mají zaznamenané, neprokázané příčiny v ADR-0040.

Release kontroly: úplná izolovaná sada včetně skutečného wheelu **513 passed / 116 expected skips**; oba produkční frontend buildy a TypeScript prošly. Následná izolace syntetického benchmarkového katalogu byla znovu ověřena všemi testy modulu v hlavním i čistém JHU stromu (20 passed / 6 expected skips v každém). Aktuální JHU projekce má 298 souborů, pouze tenant JHU; všech 445 veřejných zdrojových cest je v mapě repozitáře a kontroly syntaxe, verzí, odkazů, privátních cest a whitespace prošly. Kontrola známých privátních hodnot nenašla jejich kopie ve veřejných zdrojích; veřejná jména KV referencí nejsou hodnoty credentials.

Finální cílená sada čisté JHU projekce včetně opraveného benchmarkového modulu, transportu, modelů, administračních nastavení, PowerShell startupu a skutečného wheelu: **153 passed / 16 expected skips**.

Předchozí skutečná lokální SQL sada měla **606 passed / 23 expected skips**. Native Azure, živé modely a restart Rancheru se při běžných release regresích znovu nespouštějí; jejich dřívější důkazy a omezení jsou popsány výše.

**Cloudový managed VPN režim není implementovaný.** Současný adaptér je záměrně pouze local/test a používá lokální Docker. ACA vyžaduje samostatný sidecar/bootstrap/transport, guarded nasazení a ověření sítě i kapacity; read-only preflight a plán jsou v agentovém handoffu. GPT-5.4 deployment v JHU Azure chybí; GPT-mini a embedding deployment existují. Nasazení nových modelových tabulek, příprava cloudových embeddingových indexů, změny kapacity/RBAC/secrets a ANN aktivace jsou oddělené operace. Toto vydání nemění Azure ani samostatné Forgejo repo.
