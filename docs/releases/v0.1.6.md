# v0.1.6 — cloudové a lokální modely, embeddingové indexy a porovnání výsledků

Vydání zdrojů: **2026-10-21**, hlavní GitHub repozitář, větev `microsoft-sql`. Backend, oba frontendové balíčky/lock soubory a UI používají v0.1.6. [Changelog](../CHANGELOG.md) obsahuje podrobnosti.

## Modely a oprávnění

- Tenantový katalog a výběr modelu pro každou další otázku v uživatelské i administrační konzoli. Samostatné modely pro shrnutí a klasifikaci dokumentů; původ odpovědí se zachovává v historii.
- Cloudové profily GPT-5.4-mini/GPT-5.4 a JHU lokální API pro inference i embeddingy. Připojení se spravují mimo veřejné katalogy; chyba nevyvolává skrytý přechod k jinému modelu.
- Admin načítá inventář JHU API, explicitně přidává kompatibilní modely a nastavuje jejich publikaci a skupinová oprávnění. Server znovu ověřuje tenant a aktuální skupiny před použitím.
- Upravitelné CS/EN popisy a maximální počet výstupních tokenů. Tenantové SQL nastavení má vlastní revize a ochranu proti souběžnému přepsání; lokální kontext omezuje také přípustný vstup.

## Embeddingy a vyhledávání

- Nomic a MXBAI doplňují Azure embeddingy přes samostatné neměnné profily s rozměry, digestem a instrukcemi pro vstupy.
- Admin lokálně vytvoří/doplní další index nad existujícími chunky. Povolený a připravený index lze vybrat v obou konzolích. Každý dotaz prohledává právě **jeden index UUID**; volba nemění výchozí ingestaci.
- Kontroly profilu, pokrytí a oprávnění odmítají neplatný výběr. Nedochází k automatickému prohledávání všech modelů ani náhradnímu indexu.
- Doplnění jiného embeddingového profilu v lokálním demu zachovává existující chunky a vektory. Keyword-only dotaz nevolá embeddingovou službu.

## Admin a dokumenty

- Záložka **Modely a vyhledávání** sjednocuje vyhledatelné modelové volby, parametry, popisy, dostupnost, oprávnění a embeddingové indexy. Obnova API otevře dialog pro explicitní přidání modelů.
- **Porovnání výsledků** používá jednu otázku a dvě samostatné konverzace s nezávislými modely, indexy a filtry. Každá strana zachovává své citace, historii, časy a chyby.
- RAG, shrnovací a klasifikační prompty se upravují na jednom místě. Volby i rozepsané změny přežijí přepínání záložek.
- Produkční ingestace získává skutečné shrnutí před embeddingem; při chybě neukládá zástupný AI text. Zvolený model se zaznamenává do provenance dokumentového zpracování.

## Provoz a hranice vydání

README obsahuje explicitní tenant pro lokální spouštění a návody používají aktuální skripty. Wheel i čisté JHU předání zahrnují nové veřejné konfigurace a modelové moduly, bez soukromých env.

Nové cloudové tabulky modelových oprávnění, registru, popisů a runtime limitů vyžadují samostatné ověřené migrace (`migrate_model_access.py`, `migrate_model_registry.py`, `migrate_model_metadata.py`, `migrate_model_limits.py`). Lokální startup není potvrzení jejich existence v Azure. Dostupnost konkrétních GPT deploymentů a síťová cesta JHU se ověřují odděleně.

Součástí dokumentace je audit Key Vaultu a návrh připojení JHU. Automatická VPN, userspace proxy/sidecar ani nová VM **nejsou implementované**. Dosavadní lokální HTTP spojení vyžaduje ručně dostupnou ověřenou VPN trasu. ANN zůstává volitelná funkce; výchozí exact režim se nemění. Vydání neprovádí Azure nasazení, migraci, reindexaci ani aktualizaci Forgejo.
