# v0.1.9 — správa embeddingových indexů a průběh zpracování

Zdrojové vydání pro hlavní GitHub a samostatný JHU Forgejo snapshot. Azure rollout je samostatná uživatelem schválená operace: nová backend/helper image, oba frontendy a pouze aditivní tabulka úloh. Samotný Git tag neprokazuje dokončení cloudového nasazení.

## Funkce

- Přidání embeddingového indexu z ověřeného JHU katalogu, samostatný dopočet v menu Chunkování, trvalý SQL stav, zastavení a explicitní pokračování po přerušení. Hotové dávky se znovu nepočítají. Výchozí index ingestace je chráněn.
- Průběhové okno ukazuje soubory a aktuální dávku, krok výpočtu či ukládání, úplné pokrytí chunků i chyby. Okno lze zavřít a znovu otevřít. Stejný přehled souborů slouží také pro novou segmentaci dokumentů.
- Samostatný stav JHU a explicitní správní obnovení VPN sidecaru s kontrolou generace a zákazem překryvu inference. Pět minut ověřeného zdraví obnoví rozpočet dalších přechodných chyb; autentizační chyby nespouštějí nekonečné přihlášení.
- Bezpečné zpracování discovery chyb a výběr konkrétního embeddingového profilu. Cloudová chyba již neradí spouštět lokální FastAPI na portu 8000.

## Nasazení a hranice

Cloudový startup nevytváří tabulku úloh: vyžaduje cílený `migrate_index_jobs.py` a `INDEX_PREPARATION_ENABLED`. Žádný nový index se při releasu automaticky nepopuluje ani neaktivuje. Dokumenty, historie, účty, nastavení a dosavadní vektory se při běžné výměně image zachovávají a kontrolují pomocí checkpointů.

Indexové úlohy jsou trvalé a dávkově obnovitelné. Starší průběh nové segmentace je procesový a po restartu se nezachová; vyžaduje dostupné původní soubory. Nenahrazuje se automaticky jiným modelem nebo indexem. Relevance R_583/Nomic, ANN výkon a obnova ze zálohy zůstávají samostatná ověření.
