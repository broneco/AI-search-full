# Test Explanation: `test_rechunk.py`

This test suite verifies the background re-indexing and document re-segmentation (re-chunking) pipeline in the FastAPI backend application. It ensures that changing the document chunking parameters (such as chunk size and chunk overlap) triggers a safe database transition, updating old segments with newly split text chunks and regenerating embeddings.

---

## Individual Tests

### Test 1: `test_fast_reindex_task`

* **High-Level Purpose:**
  We verify that when search configuration chunk sizes are changed, triggering the background fast re-indexing task (`run_reindex_all_task`) successfully deletes old database chunk records, segments the original document text files according to the new sizes, fetches the new vector embeddings, and inserts them back into PostgreSQL. The update must preserve document level metadata, access control lists (ACLs), and occur within a safe, transactional boundary so that failed operations rollback to avoid leaving empty documents.
* **Low-Level Technical Details:**
  * **Database Sandbox setup:**
    * Employs the `db_setup` fixture which verifies connection status using SQLAlchemy's `engine.connect()`.
    * Clears existing records from `chunks` and `documents` tables before starting, ensuring a clean test environment.
  * **Mock Document Seeding:**
    * Writes a temporary file containing 500 characters of sample text to the local `data/` folder as `temp_rechunk_test.txt`.
    * Seeds a `DBDocument` row in PostgreSQL pointing to this mock file with custom security groups and timestamps.
    * Seeds an initial, large `DBChunk` representing old segment parameters (e.g. 1500 chars).
  * **Config Configuration:**
    * Loads the system config manager (`SearchConfigManager`).
    * Backup the original `chunk_size` and `chunk_overlap` configurations.
    * Updates `chunk_size` to `150` characters and `chunk_overlap` to `0` characters, saving it to the JSON file.
  * **Task Execution & Validation:**
    * Calls `run_reindex_all_task` inside an asynchronous `anyio` execution loop.
    * Asserts that `reindex_progress` global tracking state updates to `"completed"` with no errors.
    * Queries the PostgreSQL database to check the new `DBChunk` count: since the sample text is ~500 chars and the chunk size is set to `150`, it asserts that multiple chunks (at least 3-4 chunks) are created.
    * Asserts that all newly inserted chunks have valid 1536-dimensional float vector embeddings generated by Azure OpenAI.
    * Restores the original configuration file and deletes the temporary mock text file to leave the workspace clean.

### Test 2: `test_preview_chunks_endpoint`

* **High-Level Purpose:**
  We verify that the interactive live preview API endpoint (`POST /api/documents/preview-chunks`) accurately simulates text segmentation and returns the resulting chunks without writing anything to the PostgreSQL database. This allows admins to audit and visualize chunk boundaries in real time while adjusting settings.
* **Low-Level Technical Details:**
  * Uses the **`TestClient`** to perform HTTP requests against the FastAPI app.
  * Seeds a mock document in the database pointing to a temporary text file with 500 characters of sample content.
  * Makes a `POST` request to `/api/documents/preview-chunks` passing the `document_id` and custom parameters (`chunk_size = 200`, `chunk_overlap = 50`).
  * Asserts that the response is `200 OK` and returns a JSON list of chunk previews.
  * Asserts that the document content was correctly split into multiple chunks where each chunk size does not exceed the custom `200` characters limit.
  * Validates that the database chunks table was *not* altered by this simulation, leaving the document without actual DB updates until re-indexing is explicitly triggered.
  * Cleans up the temporary text file.

### Test 3: `test_recursive_character_splitter_strategies`

* **High-Level Purpose:**
  Verifies that different structural strategies (page-isolated, cross-page crossing, and character-only steps shifting) perform text segmentation correctly according to their mathematical models and boundary limits.
* **Low-Level Technical Details:**
  * Runs assertions directly on the `RecursiveCharacterTextSplitter` instance.
  * Passes two `ExtractedPage` page models with mock text.
  * **Page-isolated strategy check:** Verifies that page boundary isolates text: no chunk on page 1 contains characters from page 2.
  * **Cross-page strategy check:** Verifies continuous string slicing is triggered, and checks that chunks cross page limits seamlessly.
  * **Character-only strategy check:** Verifies standard non-hierarchical splitting by character limit (no separator checks).

---

### Test 4: `test_advanced_chunking_strategies`

* **High-Level Purpose:**
  Verifies that all advanced segmentation strategies (Token-based, Structure-aware, Agentic, and Semantic) split text correctly, handle custom user prompts, eliminate 100% pure overlap duplicate chunks, and respect page overlap boundaries.
* **Low-Level Technical Details:**
  * **Token-based check:** Splits text based on tokenizer encoding counts (simulating tiktoken model counts). Asserts that the resulting output returns segmented chunks.
  * **Structure-aware check:** Slices markdown text containing headings (`#` and `##`) and verifies that chunks are aligned cleanly along heading boundaries.
  * **Agentic check:** Runs the agentic splitter with `generate_summaries` enabled and custom prompt `Shrnutí v angličtině prosím`, asserting that LLM summaries are generated and correctly prepended to the chunk.
  * **Semantic check:** Employs an async `MockEmbeddingProvider` to calculate cosine similarities between sentences, computing standard deviation boundaries to split sentences on topic transitions without crashing.
  * **Pure Overlap & Cross-Page Overlap check:** Runs character splitting with `chunk_overlap = 30` over distinct words, asserting that no chunk is a 100% duplicate substring of its predecessor and that `overlap_cross_page` controls carryover across page breaks.
