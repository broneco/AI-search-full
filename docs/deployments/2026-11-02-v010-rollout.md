## Co administrace nyní umí

Z ověřeného katalogu JHU modelů lze vytvořit index a v Chunkování spustit jeho dopočet. Průběhové okno zobrazuje aktuální operaci/dávku, skutečné pokrytí chunků, jednotlivé soubory, chyby a hledání podle názvu. Okno lze zavřít a znovu otevřít z horní lišty. Indexová úloha má trvalý SQL stav, heartbeat, zastavení po probíhajícím požadavku a explicitní pokračování již uložených dávek. Ingestion default je chráněn; výběr indexu pro otázku jej nepřepíná.

Stejné okno doplňuje procesový průběh nové segmentace dokumentů. Tento starší rechunking vyžaduje dostupné původní zdroje a jeho stav není trvalou SQL indexovou úlohou; restart jej automaticky neobnovuje. Rozdíly popisuje [návod](../development/cloud-embedding-management.md).

Skutečný heslový login existujícího administrátora prošel a jeho relace přežila reload finální konzole. V GUI bylo ověřeno spuštění, dokončení, filtrování R_583, stav obou jazykových dokumentů Hotovo 3/3 a zavření/znovuotevření okna. Nomic zůstal 9372/9372, nově vypočteno 0. Jeden existující dokument nemá žádné chunky; přehled jej odlišuje jako Bez chunků. Proto je hotovo430z431 souborů, přestože všechny existující chunky mají platné vektory.

## Doložené chyby a jejich opravy

Původní cloud nebyl připojený k notebooku. Po TLS/upstream chybách zůstal VPN supervisor po třech pokusech v konečném stavu od 30. 10.; API přitom dál odpovídalo. UI rada o lokálním portu8000 byla zavádějící a původní refresh neobnovoval VPN. Nový správní reconnect je oddělený od refresh snapshotu a kontroluje generaci i aktivní inferenci. Přesný prvotní důvod TLS/upstream chyby bez JHU serverových logů doložený není.

Živá akceptace v0.1.9 navíc našla dvě nové chyby: přeskočené hotové dávky dlouho držely SQL zámek a zablokovaly heartbeat; dotaz na soubory měl pomalý outer-join plán. v0.1.10 ukončí úplný index bez provideru/průchodu, uvolní transakci každé přeskočené dávky a používá samostatné agregace se scoped INNER HASH JOIN. Stejných431 souborů/9372vektorů bylo novým přesným kódem read-only ověřeno v Azure za 0,128 s proti 14,201 s. Bez změny oprávnění nebo obsahu vektorů.
